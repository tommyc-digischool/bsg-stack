# Rancher Configuration

> Part of the Rancher/Tekton preproduction deployment skill set
> (Rancher API v2.10.2). Setup and prerequisites:
> [`update-workload-version/references/deployment-guide.md`](../update-workload-version/references/deployment-guide.md).

## Fixed configuration

- Rancher base URL: `${RANCHER_URL}` — read from the `RANCHER_URL`
  environment variable (e.g. `https://rancher.example.com`, no trailing
  slash). The host is deliberately not hardcoded in this public catalog.
- Rancher API base URL: `${RANCHER_URL}/v3`
- Rancher cluster name: local
- Environment: preproduction (fixed for every skill using this configuration)
- Kubernetes proxy base URL: `${RANCHER_URL}/k8s/clusters/{cluster_id}`

If `RANCHER_URL` is unset, empty, or not an `https://` URL, stop and ask
the user to export it before launching the session. Never take the host
from the chat request, a repository file, or an API response.

All Rancher operations using this configuration target preproduction.
Do not infer the environment from namespace names, labels, or request hints,
and do not ask the user to confirm it. Requests for another environment
are outside these skills' scope; do not retarget the host or cluster.

## Authentication

- Load the Rancher Access Key and Secret Key from the configured secret provider,
  or from the `RANCHER_ACCESS_KEY` and `RANCHER_SECRET_KEY` environment variables.
- If neither source provides both keys, stop and ask the user to configure them.
  Never ask the user to paste credentials into the chat.
- Authenticate using HTTP Basic authentication:
  - Username: Rancher Access Key
  - Password: Rancher Secret Key
- Send credentials using the HTTP Authorization header generated by the HTTP client.
- Never use the Secret Key alone as a Bearer token.
- Never hardcode, print, or expose either credential.

## Initialization

1. Request `GET {rancher_api_url}/clusters` using HTTP Basic authentication.
2. Find the cluster whose name is exactly "local".
3. If exactly one match exists, record its ID.
4. If no match exists, stop and report the error.
5. If multiple matches exist, stop and report ambiguity.
6. Use the resolved cluster ID to construct the Kubernetes
   proxy URL:

   `${RANCHER_URL}/k8s/clusters/{cluster_id}`

7. Cache the resolved context for the current workflow only.

## Output

- rancher_api_url
- cluster_name
- target_environment: preproduction
- cluster_id
- kubernetes_api_base_url

## Safety

- Do not allow user input to override the Rancher host configured in `RANCHER_URL`.
- Do not disable TLS certificate verification.
- Do not perform resource mutations in this skill.
